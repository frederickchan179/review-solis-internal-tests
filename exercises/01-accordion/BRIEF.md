# Test 01 — Accordion Component (Debug & Fix)

## Time budget
35–45 minutes.

## Scenario
You've been handed a working Accordion component for a FAQ section. It renders, expands, and collapses — but it was shipped without QA and has several issues ranging from visual bugs to accessibility gaps. Your job is to find and fix them.

## Files
- `index.html`
- `style.css`
- `script.js`
- `REQUIREMENTS.md` — read this fully before you start, and re-check your fixes against it before submitting. Some fixes that resolve a visible bug can still violate a rule stated here.

Open `index.html` directly in a browser to run it (no build step needed).

## Your task
1. Use the component as a real user would: expand/collapse items, type in the filter box, try items with short and long answers, and try navigating with only the keyboard.
2. Identify the bugs you find. There is more than one, and they span functionality, visual layout, and accessibility — don't stop after finding the first one.
3. Fix them directly in the provided files.
4. Keep the existing code style: HTML uses BEM class naming, CSS has no framework, JS is vanilla ES6 written in a functional style (no classes, prefer array methods and pure rendering functions).
5. You may use AI tools while working. If you do, be ready to explain in your own words what each bug was and why your fix addresses it — we care more about your understanding than the diff itself.

## What to submit
- The fixed `index.html`, `style.css`, `script.js`.
- A short written note (bullet points are fine) listing each bug you found and the fix you applied.

## Not in scope
You don't need to add new features (e.g. animations, new items) — focus on making the existing behavior correct and accessible.
