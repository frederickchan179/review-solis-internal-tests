# Review - 01 Accordion

### Dev: Findings

| Pri | Area | Issue | Suggestion |
|-----|------|-------|------------|
| Required | State | Which item is open is stored as `openIndex` on the *filtered* FAQ list, not by FAQ `id`. Repro: open “return policy” (index 1), type `How` in the filter → “Sizing” moves into index 1 and looks open even though the user never opened it. After filtering, the wrong answer can appear expanded. That breaks REQUIREMENTS: the open item must stay the same FAQ across filter changes. | Store the open FAQ by `id` (e.g. `openId`, or `null` when nothing is open).<br>When rendering, mark a button expanded only when `item.id === openId`.<br>Do not re-decide “what is open” from the filtered list’s indexes. |
| Required | A11y | Closed panels are only hidden with `max-height: 0` and `overflow: hidden`. They look gone, but content stays in the page. The sizing answer still has a real `<a href="#">`, and Tab can land on that link while the panel looks closed. Keyboard users can focus a link they cannot see. REQUIREMENTS: closed content (including links) must not be reachable with Tab. | Hide closed panels from assistive tech and keyboard focus (`hidden` / `inert`), or remove/disable focusable controls while closed.<br>CSS height alone is not enough. |
| Required | Layout | Open panels are locked to `max-height: 200px`. The short shipping answer often still fits, so the bug is easy to miss on a tall screen. Longer text, zoom, or a narrow window cuts the answer off with no scroll inside the panel. REQUIREMENTS: long answers must be fully readable when open. | When open, let the panel grow with the content, or allow scroll inside the panel.<br>Remove the hard `200px` cap so answers are not permanently cut off. |
| Optional | HTML | The filter only has a placeholder, so it has no clear accessible name (placeholders are not a reliable label). It is `type="text"` instead of `type="search"`. The FAQ block is a plain `<div id="accordion">`, not a named section. | Add a visible `<label>` or `aria-label` on the filter.<br>Prefer `type="search"`.<br>Wrap the FAQ in a named `<section>`. |
| Optional | A11y | Buttons already expose `aria-expanded`, but panels lack stable `id` / `aria-controls`, so screen readers cannot reliably connect the header to its content. The decorative `+` is read aloud as text. Filter and accordion buttons have no `:focus-visible` style, so keyboard focus is hard to see. | Give each panel an `id` and point the button at it with `aria-controls`.<br>Hide the decorative `+` with `aria-hidden="true"`.<br>Add `:focus-visible` on the filter and accordion buttons. |
| Optional | UX | Filtering is case-sensitive and only searches `question`, not `answer`. When nothing matches, the list goes blank with no “No results” message. The sizing support link uses `href="#"`, which jumps to the top of the page. | Make filtering ignore case and search both question and answer.<br>Show a clear empty message when nothing matches.<br>Use a real URL, or call `preventDefault` on the support link. |
| Optional | JS | Every toggle and filter rebuilds the whole list with `innerHTML` and re-attaches click listeners. The filter also re-renders when the query is unchanged after `trim`. DOM variable names and null-checks are inconsistent (`accordionEl` vs bare queries). | Prefer one click listener on `#accordion` (event delegation) instead of rebinding every button.<br>Skip re-render when the trimmed query did not change.<br>Keep DOM names consistent (`*El` / `*Btn`) and null-check `getElementById` / `querySelector` before use. |
| Optional | CSS | CSS property order jumps around between rules. The icon rotate animation always runs and ignores `prefers-reduced-motion`. | Pick one property order (positioning → display → box → type → visual).<br>Turn off or shorten the icon rotate when `prefers-reduced-motion: reduce`. |

| Required | Clip | The shipping answer still fits under the `200px` open cap on many screens.
